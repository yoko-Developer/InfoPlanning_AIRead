# OCRソフトウェア VerUp前後CSV判定仕様書

## 1. 概要
OCRソフトウェアのバージョンアップ前後で出力される有価証券CSVファイルの構造が異なるため、CSVファイルを読み込んで自動的にバージョンを判定する仕様を定義する。

## 2. 判定対象ファイル
- **VerUp前**: `sample_before\有価証券\*.csv`
- **VerUp後**: `sample_after\有価証券\*.csv`

## 3. 主要な差異

### 3.1 ItemName（列名）の構造変化

#### VerUp前の特徴
- **詳細な列名**: 各項目が個別の列名として定義されている
  - `区分` - 種類/銘柄が別々の行
  - `amount_1` - 数量のみ
  - `期末現在高` - 金額のみ
  - `amount_3` - 異動年月日/異動事由が別々
  - `期中` - 数量のみ
  - `増(減)の` - 金額のみ
  - `明細` - 売却先名称/所在地が別々
  - `amount_7` - 摘要のみ

#### VerUp後の特徴
- **統合された列名**: 複数の項目が1つの列名に統合されている
  - `区分` - 区分のみ（種類銘柄は別列）
  - `種類銘柄` - 種類と銘柄が統合
  - `数量_01` - 数量（第1）
  - `期末現在高` - 空（ヘッダーのみ）
  - `金額` - 金額
  - `異動年月日` - 異動年月日
  - `数量_02` - 数量（第2）
  - `異動事由` - 異動事由
  - `期中増(減)の明細売却(買入)先の名称(氏名)金額` - 長い統合列名
  - `売却(買入)先の所在地(住所)` - 所在地
  - `摘要` - 摘要

### 3.2 データ構造の変化

#### VerUp前
- 種類と銘柄が同じ`区分`列に別々の行として格納
- 数量と単位が別々の行（例: "口" と "2,434"）
- 小計行が明確（例: "計", "正券計", "金計"）

#### VerUp後
- 種類と銘柄が`種類銘柄`列に統合されて格納
- 数量と単位が同じ行に統合（例: "ロ 2,434"）
- 小計行の表現が変化（例: "出資金計", "投資有価証券計", "関係会社出資金計"）

## 4. 判定ロジック

### 4.1 判定基準（優先順位順）

#### 【判定1】列名の存在チェック（最優先）
VerUp後にのみ存在する列名をチェック：
- `種類銘柄` が存在する → **VerUp後**
- `種類銘柄` が存在しない → **VerUp前の可能性が高い**

#### 【判定2】統合列名のチェック
VerUp後の特徴的な長い列名をチェック：
- `期中増(減)の明細売却(買入)先の名称(氏名)金額` が存在する → **VerUp後**
- `明細` と `増(減)の` が別々に存在する → **VerUp前**

#### 【判定3】数量列名のパターンチェック
- `数量_01` と `数量_02` が存在する → **VerUp後**
- `amount_1` と `期中` が存在する → **VerUp前**

#### 【判定4】データパターンのチェック（補助的）
`区分`列のGrupID="0"の行で、Valueに以下が含まれるかチェック：
- "種類" と "銘柄" が別々の行として存在する → **VerUp前**
- "その他" のみで種類銘柄が別列 → **VerUp後**

### 4.2 判定アルゴリズム

```
1. CSVファイルを読み込む
2. ItemName列のユニークな値を取得
3. 以下の順序で判定：
   
   IF "種類銘柄" が存在する THEN
       return "VerUp後"
   
   IF "期中増(減)の明細売却(買入)先の名称(氏名)金額" が存在する THEN
       return "VerUp後"
   
   IF ("数量_01" AND "数量_02") が存在する THEN
       return "VerUp後"
   
   IF ("amount_1" AND "amount_3" AND "amount_7") が存在する THEN
       return "VerUp前"
   
   IF "明細" が存在する THEN
       return "VerUp前"
   
   ELSE
       return "判定不能"
```

## 5. 実装上の注意点

### 5.1 文字コード
- CSVファイルはUTF-8エンコーディング
- 日本語列名を含むため、文字コード処理に注意

### 5.2 列名の正規化
- 列名の前後の空白を除去してから比較
- 大文字小文字は区別する（日本語列名のため）

### 5.3 エラーハンドリング
- CSVファイルが破損している場合
- 想定外のフォーマットの場合
- 必須列（ItemName, Value等）が存在しない場合

## 6. テストケース

### 6.1 VerUp前の判定テスト
- `sample_before\有価証券\有価証券01_0.csv` → "VerUp前"
- `sample_before\有価証券\有価証券01_1.csv` → "VerUp前"
- `sample_before\有価証券\有価証券02_0.csv` → "VerUp前"

### 6.2 VerUp後の判定テスト
- `sample_after\有価証券\有価証券01_0.csv` → "VerUp後"
- `sample_after\有価証券\有価証券01_1.csv` → "VerUp後"
- `sample_after\有価証券\有価証券02_0.csv` → "VerUp後"

## 7. 判定結果の活用

判定結果に応じて、以下の処理を分岐：

### VerUp前の場合
- 既存の処理ロジックを適用
- `区分`列から種類と銘柄を分離して取得
- `amount_1`, `amount_3`, `amount_7`等の列名を使用

### VerUp後の場合
- 新しい処理ロジックを適用
- `種類銘柄`列から直接データを取得
- `数量_01`, `数量_02`, `金額`等の列名を使用
- 統合された列名に対応した処理

## 8. 判定精度

### 高精度判定が可能な理由
1. 列名の構造が明確に異なる
2. 複数の判定基準を組み合わせることで誤判定を防止
3. VerUp後の特徴的な列名（`種類銘柄`等）が決定的な判定材料となる

### 想定される判定精度
- **正判定率**: 99%以上（列名が正しく出力されている場合）
- **誤判定リスク**: 列名が破損または改変されている場合のみ
